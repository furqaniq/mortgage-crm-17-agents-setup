# AGENTS.md conflict resolutions — 17-agent roster

How the 17 per-agent `AGENTS.md` files in this folder were kept consistent with each other and with `AGENT_HANDBOOK_17_SMALL_TEAMS_v6.md` (version 5 until CANVAS was reinstated). Each resolution is written into **both** files it touches, so neither agent's rulebook can be read as an exemption from the other's.

**Layout.** `instruction files/<Division>/<CODENAME>/AGENTS.md` — Command (SOPHIA, ATLAS, AEGIS), Revenue (SCOUT, PULSE, ECHO, VOX, TEMPO, FORGE, EMBER), Marketing (QUILL, CANVAS, RELAY), Operations (CIRCUIT, LEDGER, WARDEN, COMPASS). Every file follows `AGENTS_md_format.md`, with the adaptations listed under *Format adaptations* below.

---

## Resolution principles

Carried from the 24-agent pass, plus two added for this roster:

1. **The handbook wins** — but where it gives two agents the same authority, the split is written into both files.
2. **Specific policy beats general authority.** A cap that exists for a regulatory reason overrides a blanket claim over "every agent."
3. **One enforcement point per rule.** Many agents may detect, observe, or report; exactly one enforces.
4. **Handoffs are stated on both sides.**
5. **One channel to people, one delegator of work.** Only SOPHIA talks to staff; only ATLAS assigns agent work. Every "escalate to a human" in a specialist's file means *to ATLAS, which brings it to the human through SOPHIA*.
6. **Specify, then the owner applies.** An agent that designs configuration for another agent's surface hands the specification over; it never writes into that surface to save time.

## Keeping the set consistent

Before changing any one file:

- Adding or rewording an **Owns** entry → search the other sixteen files for that surface.
- Writing **"every agent," "only," or "across the roster"** → either this agent is the single enforcer (say so in the constrained agents' files too) or downgrade to *reads* / *observes* / *reports*.
- Adding a **handoff** → add it to the receiving agent's §4 in the same edit, and route it through ATLAS.
- Adding anything that **reaches a person** → it goes through SOPHIA.
- Adding anything that **sends** → gated send tool, approval ID, and AEGIS review stage.
- Adding a **dependency** → state the agent's safe default when it is down, missing, or stale.
