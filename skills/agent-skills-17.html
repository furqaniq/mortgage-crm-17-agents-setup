Each AGENTS.md says what its agent owns, what it must escalate, and what it must never do. None of them says how the work is done — that is what skills carry, and it is the reason the set rates 3.0 / 5 on operability and 2.5 / 5 on mortgage knowledge.

A skill here is one unit of work you could scope, build and test on its own: the thing you would hand to an engineer, or define as one tool in an agent's toolset. It is not a restatement of a responsibility bullet, and it never restates a rule that already lives in the handbook.

Two marks matter. Interlock means the skill implements that agent's Hard boundary in version 6 — it exists because the law, not a product decision, requires it, and it cannot be switched off. Build first marks the skills that close a gap already named in AGENTS_md_known_limitations.md for the lowest-scoring agents.

Where each one lives

skills/<Division>/<CODENAME (Hire Title)>/<skill-name>-<codename>/SKILL.md — every skill name ends in its agent's codename in lowercase, so dual-axis-scorer-pulse is PULSE's wherever it turns up.

Frontmatter: name, description, agent, division, binding — interlock where marked below, otherwise mandate, since every agent in this roster has §5 Hard Rules.

Body, always these six: When this fires · Inputs · Procedure · Output · Hard rules · Measured on. Hard rules come in two groups — the agent's whole AGENTS.md §5 inherited verbatim, then the rules only this skill can break.

Format carried from the 24-agent company's SKILLS_FOLDER_STRUCTURE.md. Where a skill and the handbook disagree, the handbook wins.
